## 한눈에

- 첫 실험 범위: **도구 고르기**(한국어/영어 요청 → 맞는 도구 또는 "부르지 않음").

- 성공 기준: 골드셋에서 **프론티어 모델과 2점 이내**, 100배 이상 싸고 빠름, CPU 단계당 0.2초 이내.

## 1. 툴콜의 정의
- **툴콜** = 모델이 직접 답하는 대신 "이 도구를 이 값으로 실행해 줘"라고 요청하는 것. 실행은 에이전트 프로그램이, 결과는 모델에게 돌아감. 모델은 결과를 읽고 다음 호출 또는 최종 답.
- 어떤 태스크에 어떤 도구를 부르나:

| 태스크 성격 | 부를 도구 | 예 |
|---|---|---|
| 모델이 모르거나 바뀌는 정보 | 조회 | 날씨, 환율, 오늘 일정, 서버 상태 |
| 바깥 세상을 바꾸는 일 | 행동(위험하면 먼저 확인) | 일정 등록, 메일 발송, 재시작 |
| 정확한 계산·실행 | 계산/코드 실행 | 날짜 계산, 합계 |
| 이미 아는 것·대화로 충분 | 부르지 않음(이것도 정답) | 개념 설명, 인사 |

- **툴콜 능력 = 다섯 판단:** ①부를지 말지 ②무엇을 ③인자(값·형식) ④순서(앞 결과가 다음 인자) ⑤결과 활용과 실패 회복.
- 정답은 하나가 아님 → 태스크마다 "허용 경로 + 꼭 지킬 조건 + 금지 행동"으로 정의.
- 예: "다음 주 화요일 오후 빈 시간에 회의 잡아줘" → 날짜 확인 → 화요일 일정 조회 → 빈 시간 선택 → 등록 → 결과로 답. 틀린 예: 조회 없이 등록, 날짜 오류, 겹치는 시간 등록, 실패를 성공이라 말함.

## 2. 연구 질문과 가설
**질문:** CPU에서 도는 아주 작은 채점 모델이 툴콜을 프론티어 모델만큼 채점할 수 있나?

- H1: 좁은 범위(도구 고르기)에서 0.1~0.4B 학생 모델이 골드셋 기준 프론티어 모델(제로샷 심판)과 2점 이내.
- H2: 사람 검수 라벨로 배운 학생이 검수 전 강한 모델 라벨로 배운 학생보다 낫다(사람 검수의 값어치).
- H3: 학생은 강한 모델(선생)의 실수를 일부 고쳐 선생보다 골드셋 점수가 높을 수 있다.
- H4: 범위를 인자·순서·결과 활용으로 넓히면 학생과 프론티어의 격차가 커진다.
- H5: 학생 확신이 낮은 건만 큰 모델로 넘기면(계단식), 넘김 20% 이하로 프론티어 수준을 낸다.

## 3. 성공 기준 (임시값, 첫 실험 후 확정)
| 지표 | 기준 |
|---|---|
| 골드셋 정확도 | 프론티어 기준선 − 2점 이내 |
| 사람 대비 일치도 (Cohen's kappa: 우연 일치를 뺀 일치율) | 사람끼리 일치도에 근접 |
| CPU 속도 | 단계당 ≤ 0.2초 |
| 비용·속도 | 프론티어 대비 100배 이상 저렴·빠름 |
| 편향 | 문장 길이·한영 여부에 따른 점수 차 없음 |

## 5. 데이터 (3,000건, 검수자 3명)
| 묶음 | 건수 | 라벨 방식 | 용도 |
|---|---|---|---|
| 학습 | 2,400 | 강한 모델 라벨 → 1명 검수 | 학생 학습 |
| 검증 | 300 | 강한 모델 라벨 → 1명 검수 | 설정 고르기 |
| 골드(시험) | 300 | 3명 독립 라벨 → 다수결 | 최종 평가 전용 |

- **사람끼리 일치도**(골드 3명)가 모델 목표의 상한.
- 1인 분량 약 1,200건, 1건 20~30초 → 8~10시간(추정).
- 한 건의 구성:

| 부분 | 내용 |
|---|---|
| 문제 | 사용자 요청(+이전 대화), 도구 목록(이름·설명·인자 형식), 가상 환경 데이터 |
| 정답 | 허용 경로, 꼭 지킬 조건, 금지 행동 |
| 풀이 | 에이전트의 실제 호출·인자·결과·최종 답 (도구 고르기 단계에서는 고른 도구) |
| 사람 확정 라벨 | 좋음/나쁨 + 판단 항목별 점수 + 짧은 이유 |

- 문장 구성: 쉬운 문장만 넣으면 금방 100점 → 헷갈리는 문장 필수.
  - 부르지 않음: "캘린더가 뭐야?"
  - 두 도구·순서: "내일 비 안 오면 캘박해줘" (날씨 → 캘린더)
  - 못 하는 일: "어제 날씨 어땠어?" (과거 날씨 도구 없음 → 못 한다고 답)
  - 한영 혼용: "tomorrow 일정 add 해줘"
  - 비율(안): 쉬운 40%, 헷갈림 40%, 부르지 않음·못 함 20%.
- 데이터 출처: 테스트벤치(blog llm-grading)의 가상 도구·툴콜 문항 + 새로 만든 문장 + 일부러 망가뜨린 풀이(합성 오답). Hermes 실제 로그는 로컬 처리·익명화 전제(결정 대기).

- **미세조정 추천:** 이미 한/영을 아는 소형 다국어 모델에 3,000건 학습. 3090 1장 5~30분(추정). 처음부터 학습은 언어 사전학습이 필요해 비현실적.

- **프론티어 기준선:** 같은 골드셋을 프론티어 모델이 제로샷으로 채점한 점수.

## 8. 위험과 대응
- 선생 모델 편향이 그대로 전달 → 사람 검수, 골드는 사람만.
- 과적합(문장 외우기) → 골드 문장은 학습 문장과 표현·주제가 겹치지 않게, 일부는 3명이 직접 작성.
- 쉬운 문제로 착시 → 헷갈림 비율 유지, 유형별 정확도 따로 보고.
- 새 도구 추가 시 재학습 → 학습이 수십 분이라 감수, 처음 보는 도구는 계단식으로 큰 모델에 넘김.
- 개인정보 → 실제 로그는 로컬 전용·익명화.
